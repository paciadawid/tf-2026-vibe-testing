# FD-08 · Page not found — exploration notes

Explored against https://foodora.lovable.app on 2026-09-24, with Playwright MCP from a clean state
(localStorage and sessionStorage cleared).

## Routes

| Route tried | What renders | Page title |
| --- | --- | --- |
| `/this-page-does-not-exist` | the 404 page | `Page not found \| Foodora` |
| `/menu/deep/nested-path?x=1` | the 404 page (nested path and query string behave the same) | `Page not found \| Foodora` |
| `/restaurant/does-not-exist` | a *Restaurant Not Found* screen inside the normal layout, not the 404 page | `Foodora — Food Delivery from Local Restaurants` |
| `/product/does-not-exist` | a *Product Not Found* screen, not the 404 page — loads late (blank for a moment) | `Foodora — Food Delivery from Local Restaurants` |
| `/order/FDR-000000` (never placed) | a full tracking page, *Total Paid* `$0.00` — FD-07 territory, out of this scope | `Order #FDR-000000 — Tracking \| Foodora` |

The 404 page is rendered in place by the client router: the URL stays as typed, the app logs a
console error `404 Error: User attempted to access non-existent route: <path>`. The page has no
header navigation (no Foodora logo link, no Cart).

## Elements (role and accessible name as the snapshot shows them)

404 page (`/this-page-does-not-exist`):

- `main`
- `heading "404 — Page not found" [level=1]`
- `paragraph`: *Sorry, we couldn't find that page.*
- `link "Return to Home"` → `/url: /`. Clicking it lands on `/` (landing page, `heading "Popular
  Restaurants" [level=2]` present).

`/restaurant/does-not-exist`:

- `navigation` with `link "F Foodora"`, `button "New York, NY"`, `link "Sign In"`, `button "Cart"`
- `heading "Restaurant Not Found" [level=1]`
- `paragraph`: *The restaurant you're looking for doesn't exist.*
- no `Return to Home` link

`/product/does-not-exist`:

- no navigation at all
- `heading "Product Not Found" [level=1]` — appears only after the product lookup finishes
- `paragraph`: *The product you're looking for doesn't exist.*
- no `Return to Home` link

## Content that loads late

- `/product/<unknown id>` renders an empty body first, then *Product Not Found*.
- The 404 page itself renders immediately.

## Where the app already contradicts the spec

Spec: "Any address that is not a Foodora page shows **404 — Page not found** and a **Return to
Home** link."

- For a made-up path (`/this-page-does-not-exist`, `/menu/deep/nested-path`) the app matches the
  spec.
- Whether `/restaurant/<unknown id>` and `/product/<unknown id>` count as "not a Foodora page" is
  not stated. If they do, the app contradicts the spec: it shows *Restaurant Not Found* /
  *Product Not Found* without the 404 heading and without a **Return to Home** link, and the product
  page gives no way back at all (no header either). Raised as checkpoint candidates.
