How the run went

Preflight

Address, browser, config checked. Resumed from the earlier run: FD-08 was already covered.

Explore in parallel

Three agents, one per flow group: FD-01/02, FD-03/04 and FD-05/06/07. One drove the Playwright MCP browser; the other two used their own browsers.

One question

51 new rules were put to the team, with three hard-to-reach cases as extras. The team kept the plan as it was.

Build and triage

The same agents wrote the tests from their notes. A red test was either fixed, if the test was wrong, or annotated as a bug, if the app was wrong.

Rule check

check-suite.sh: every test has its story ID, a tag and the spec line it checks.

Independent audit

A fresh agent checked 183 assertions against the spec. It found 3 values copied from the app and 10 checks weaker than the spec; all 13 were fixed.

Stability

Every test was run 3 times. The slow live backend caused timeouts, and those were fixed at the cause, never by retrying until green.

Final run

Full suite: 39 pass, 13 app bugs, 0 flaky. Written to report.html.

What we learned along the way

  • The audit earned its place. Checks like “some card shows a promotion” and “Cart shows /1/” passed, but they checked less than the spec says. After tightening, one more bug surfaced: the empty cart's way back.
  • A test that passes on a bug is a bug in the test. The dish-name search test was first green because it read the list before the list had re-filtered. It now waits for the list to change, and correctly fails.
  • The flaky runs came from a slow backend, not from wrong assertions.
    • Page loads waited for every image. They now wait only for the HTML, and the test itself waits for the content it needs.
    • Restaurant data now gets a longer wait, because it comes from the backend after the page renders.
    • The cart panel is closed with its Close button, which is reliable, instead of Escape.
  • Controls without names make tests brittle, too. Quick-add and the quantity −/+ buttons have no accessible name, so they can only be found by their position or icon. The accessibility bug (FD-03) and the test design are the same problem.
  • One run was interrupted. The FD-05/06/07 builder stopped after writing its files. The lead ran and triaged those tests itself, and found one broken test, the FD-06 order summary.

Seen outside scope

  • FD-08: /restaurant/<unknown id> and /product/<unknown id> show their own “Not Found” screens with no Return to Home. The product one has no header either, so there is no way back.
  • FD-01 / FD-07 a reading: checkout, confirmation and tracking show “25-35 min” for every restaurant, while the cards advertise other ranges.
