# FD-02 · Search and filter — exploration notes

Explored against https://foodora.lovable.app on 2026-09-24, with `explore.mjs` (fresh browser
context per call, clean storage). Everything happens on `/`.

## Routes

- `/` only. Search, chips and the empty state all render in place — the URL never changes (no
  query string), and pressing Enter or **Search** does not navigate.

## Elements (role and accessible name as the snapshot shows them)

- `textbox "Search for restaurants or dishes..."` (accessible name is the placeholder)
- `button "Search"` (use `exact` — the name is also a substring elsewhere)
- chips: `button "All"`, `button "Pizza"`, `button "Burgers"`, `button "Sushi"`, `button "Italian"`,
  `button "Mediterranean"` — no `aria-pressed`/selected state in the accessibility tree.
- results: the same card `link "<restaurant name>"` elements as FD-01, under
  `heading "Popular Restaurants" [level=2]`.
- empty state: `paragraph` *No restaurants found* and `paragraph` *Try a different search or cuisine
  filter*.

## Observed results

| Action | Cards shown |
| --- | --- |
| type `burger` / `BURGER` / `bur` | Burger Palace |
| type `sushi masters` | Sushi Masters |
| type `japanese` | Sushi Masters (cuisine text is searched too) |
| type `koliba` | Koliba u Jána (with its *Not available* badge) |
| type `burger` + click **Search** / press Enter | Burger Palace (same as typing) |
| type `Classic Beef` | *No restaurants found* |
| type `Margherita` (a Pizza Corner dish) | *No restaurants found* |
| type `zzzqqq` | *No restaurants found* / *Try a different search or cuisine filter* |
| chip Pizza | Pizza Corner |
| chip Burgers | Burger Palace |
| chip Sushi | Sushi Masters |
| chip Italian | Pizza Corner |
| chip Mediterranean | Mediterranean Delight |
| chip Pizza, then All | all 5 (Burger Palace, Mediterranean Delight, Pizza Corner, Sushi Masters, Koliba u Jána); search box emptied |
| chip Pizza, then type `burger` | Burger Palace |
| type `burger`, then chip Pizza | Pizza Corner — and the search box now reads `Pizza` |

- A chip is implemented as a search term: clicking it writes the cuisine name into the search box,
  replacing what the customer typed. Typing replaces the chip. The last action wins.
- While a search or chip is active the subtitle is *Order from the best restaurants near you*; the
  *— 1 don't deliver there* count returns after **All**.

## Content that loads late

- Cards load after the first render; wait for `link "Burger Palace"` before typing, otherwise the
  empty state may flash.

## Where the app already contradicts the spec

- Spec: "The search box finds restaurants by **restaurant name** or by **dish name**. *"Classic
  Beef"* finds the restaurant that serves the Classic Beef Burger." — `Classic Beef` (and
  `Margherita`) give *No restaurants found*; only restaurant name and cuisine are searched.
- Spec: "A search and a selected cuisine chip apply **together**: with **Pizza** selected, searching
  *burger* shows only restaurants that match both." — Pizza + `burger` shows Burger Palace (not a
  Pizza restaurant); `burger` then Pizza shows Pizza Corner and overwrites the search text. The two
  never combine. Expected: no Pizza restaurant matches *burger* → *No restaurants found*.
- Case-insensitivity, live results, **Search** button, single chips, **All** and the empty state
  match the spec.
