# FD-03 · Restaurant menu — exploration notes

Explored against https://foodora.lovable.app on 2026-09-24, with `explore.mjs` (fresh browser
context per call) and, for the unnamed quick-add buttons that `explore.mjs` cannot target by
name, a short throw-away Playwright script scoped to the dish card.

## Routes

| Route | What renders |
| --- | --- |
| `/restaurant/1` | Burger Palace — has a promotion (*20% OFF orders over $25*), fee `$2.99`, tabs Burgers / Sides / Drinks |
| `/restaurant/2` | Pizza Corner — **no** promotion, fee `Free`, tabs Pizzas / Pasta / Desserts |
| `/restaurant/koliba-u-jana` | opens a full menu (Slovak) although the landing page marks it *Not available at your address* (FD-01, outside scope) |
| `/restaurant/does-not-exist` | *Restaurant Not Found* screen (see `fd-08.md`) |

Landing page cards are `link "<restaurant name>"` → `/restaurant/<id>` (Burger Palace = `1`).

## Elements (role and accessible name as the snapshot shows them), `/restaurant/1`

Header (`navigation`): `link "F Foodora"`, `button "New York, NY"`, `link "Sign In"`,
`button "Cart"` — after quick-add it becomes `button "Cart 1"`, then `button "Cart 2"` (the count
is part of the accessible name; it counts items, not lines).

Restaurant info:

- `img "Burger Palace"`, `heading "Burger Palace" [level=1]`
- `paragraph`: *American, Burgers* (cuisines), then a description paragraph
- text *20% OFF orders over $25* (promotion)
- text *4.8 (1234 reviews)* (rating)
- text *25-35 min* (delivery time), text *123 Main St, New York, NY*
- `paragraph "Delivery Fee"` followed by `paragraph "$2.99"`

Menu:

- `tablist` with `tab "Burgers" [selected]`, `tab "Sides"`, `tab "Drinks"`; one visible
  `tabpanel "<category>"` at a time. Clicking a tab swaps the panel in place (no navigation).
  - Burgers: Classic Beef Burger $12.95 (bp-1), Chicken Deluxe $14.99 (bp-2), Veggie Supreme
    $11.99 (bp-3), Double Smash Burger $15.99 (bp-4)
  - Sides: Truffle Fries $8.99 (bp-5), Onion Rings $6.99 (bp-6), Coleslaw $4.99 (bp-7)
  - Drinks: Classic Lemonade $3.99 (bp-8), Milkshake $6.49 (bp-9)
- Each dish is one `link` whose name is all of its text, e.g.
  `link "Classic Beef Burger Popular Juicy beef patty ... $12.95 Classic Beef Burger"` →
  `/url: /product/bp-1`. Inside: `heading "Classic Beef Burger" [level=3]`, optional text
  *Popular*, `paragraph` (description), text *$12.95*, `button` (quick-add, **no name**, an icon
  only), `img "Classic Beef Burger"`.
  - Locator for a test: `page.getByRole('link', { name: /^Classic Beef Burger/ })`, and the
    quick-add inside it `.getByRole('button')`.
- The quick-add button sits **inside** the dish link (interactive inside interactive).

## Behaviour

- Quick-add (card's button): stays on `/restaurant/1`, a toast in `region "Notifications (F8)"`
  says *Added to cart! Classic Beef Burger has been added to your cart.*; header goes
  `Cart` → `Cart 1` → `Cart 2` on a second click. The cart panel (`dialog "Your Cart (1)"`) then
  shows Classic Beef Burger, Burger Palace, $12.95, quantity 2.
- Clicking the dish heading opens `/product/bp-1` (client-side navigation).
- Toast close button is also unnamed (`button` with an x icon).

## Content that loads late

- Restaurant cards on `/` and the menu on `/restaurant/<id>` render after data loads — wait for a
  dish heading (e.g. *Classic Beef*) before asserting.

## Where the app already contradicts the spec

- Spec: "Every button can be used with a screen reader: each one has an accessible name that says
  what it does, including icon-only buttons such as quick-add." — every quick-add button on the
  restaurant page is `button` with **no accessible name** (an icon only). The toast's close
  button has no name either.
- Not a contradiction but a reading: *promotion* — Pizza Corner and Sushi Masters have none; test
  the promotion on Burger Palace.
