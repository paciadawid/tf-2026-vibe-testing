## Where the app already contradicts the spec

- "**Add-ons** — pick **any combination**, including none (for example *Extra Cheese* **and**
  *Bacon*)." — add-ons are radio buttons; choosing Bacon unchecks Extra Cheese, so only one
  add-on can be picked (price +$2.00, not +$3.50).
- "The cart is reachable from this page, the same as from every other page in the order flow." —
  the dish page has no header and no Cart button.
- "The **Add to Cart** button shows the price of what is configured, and updates as the customer
  changes size, add-ons or quantity." — after adding, it shows `$12.95` although Large and Bacon
  are still checked (configured price $17.95).
- "**Size** — pick exactly one" — no size is checked on load (price treated as Regular); the
  dish can be added with none selected. Reading: a customer expects one size chosen at all times.
- Every product shows the same options, prep time and calories (lemonade with Extra Patty,
  520 kcal) — looks like placeholder data; no spec line forbids it.
- The unnamed heart, share, minus and plus buttons also fail FD-03's screen-reader rule if it is
  read as covering every page.
