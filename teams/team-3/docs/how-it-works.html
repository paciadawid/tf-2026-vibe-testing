How our agentic test builder works

Team 3 · Coding agent + Playwright MCP. One prompt turns a product spec into a Playwright suite that is traced rule by rule to the spec. The agent explores the live app to learn how to test; the spec alone says what is right. Nothing about the app is hard-coded: the address comes from FOODORA_URL, the stories from spec/.

Ground rules

  • The spec wins. When the app disagrees, the red test is the finding.
  • One rule, one test — a failure never hides the rules after it.
  • No address in tests — the same suite runs on any build.
  • Scripts, not judgement, for anything that can be checked mechanically.
  • Resumable — stop at any point, run again, it picks up.

Why it is fast

  • Flows explored and built in parallel by sub-agents.
  • A worker keeps its exploration in mind when it builds.
  • Stories explored before are skipped on resume.

What lives where

  • .github/skills/team-3-build-suite/ — the skill: SKILL.md, phase files, scripts
  • .github/skills/team-3-triage-run/ — the re-run skill
  • teams/team-3/tests/ — the suite
  • teams/team-3/specs/ — notes, coverage.md, audit.md, report.html
Reusable on another app by changing the Inputs table in SKILL.md only: suite folder, spec folder, address variable, story order and flow groups.
